# Помощник по планированию релизов

[Открыть план следующего релиза](https://github.com/dbzubov/administrator-releases/issues/1).

## Как работает пилот

Новые, изменённые и закрытые Issues автоматически обновляют одну страницу плана.
В ней видны блок, предварительный приоритет, версия/ОС, недостающие данные,
возможные повторы и проверки для исправления. Причины ошибок и трудозатраты по
публичному сообщению не утверждаются. Классификация на правилах, без платного AI.
Вложения не скачиваются. Возможные дубли не закрываются и не объединяются.

План включает открытые обращения, кроме самой страницы плана и отложенных через
метку `later`. У отложенных есть отдельный список, их можно вернуть снятием метки.
Метки `in-progress` и `needs-verification` показывает сопровождающий, автоматического
выполнения или подтверждения исправлений нет. `priority:critical`/`priority:high`
позволяют сопровождающему уточнить предварительный приоритет.

## Согласование владельцем

На странице плана скопируйте текущую команду `/approve-plan <код плана>` в новый
комментарий. Только **dbzubov** может согласовывать. Команды в чужих комментариях,
тексте ошибок, PR, цитатах и отредактированных старых комментариях разрешением
не являются. При изменении обращений/меток/правил код плана меняется и старое
согласование теряет силу. `/request-changes` возвращает план на проработку;
удаление или изменение команды отзыва не восстанавливает прежнее согласование.
`/refresh-plan` обновляет страницу вручную.

Согласование означает «состав работ принят». Для реализации передайте ссылку
на план в Codex: этот пилот **не запускает код, не создаёт PR, не собирает и не
публикует релизы**. Технические детали и PR остаются в закрытом исходном
репозитории. Последний успешный сценарий сборки и доставки не меняется.
Обновления приложения устанавливаются вручную.

## Где смотреть результат

- План: Issue #1; история обсуждения/согласований в комментариях.
- Исходные обращения: Issues, текущие состояния и метки.
- Выполнение бота: Actions → Release planning assistant.
- Готовые установщики: Releases.

Редактируется ботом описание плана; замечания оставляйте в комментариях.
Закрытие Issue #1 приостанавливает обновление. Для возобновления откройте страницу
и отправьте `/refresh-plan`. Workflow можно отключить в Actions.

## Пределы и данные

Пилот показывает до 80 активных обращений. При переполнении он явно сообщает об
этом и отключает согласование; нужно отложить часть работ. Большие списки не
обрезаются незаметно. Данные за пределы GitHub не отправляются. Не публикуйте
API-ключи, пароли или конфиденциальные материалы. Заголовки и версия/ОС проходят
экранирование и удаление типовых секретов; это не замена проверке перед публикацией.

Workflow читает доверенный main репозитория дистрибутивов; имеет только
`contents: read`, `issues: write`. Прав на исходники, публикацию релизов или
выполнение команд из обращений у него нет. Отдельный ручной publisher релизов
не изменяется. Постоянные сторонние API-ключи для этого пилота не нужны.
